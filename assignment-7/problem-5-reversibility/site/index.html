Reversibility / ERA V5 · Assignment 7 · Problem 5
Kronecker embeddings · can the embedding be run backwards

The codec was never the thing that was broken.

The objection is that a trained network emits 0.31 where the codec wrote 0.30, so exact inversion looks unreachable and a variational point cloud looks necessary. That reasoning assumes decoding needs the values. It does not. Each column of the code is one hot, so decoding is an argmax down each column, and an argmax needs correct ranking. Below is how much room that leaves, and what it does and does not buy.

Q

What the assignment asked

The briefKronecker is forward deterministic (same word will always give same embedding). How do I make a reverse of this (same embedding gives the same Kronecker)? If we can do this, then we can get rid of the final head as well! Then we can have a vocab of 1M as well without any issues!

Three promises: reverse it, delete the head, get a huge vocabulary free. The first two hold. The third gets a split verdict, and saying so is more useful than pretending otherwise.

E2

How much error the decode actually tolerates

The codec output is z-normalised, so its own standard deviation is exactly 1 and noise can be quoted as a multiple of the signal's own scale. Two decoders are shown, because they fail differently: one is told the token's length, the other has to infer it from the column margin, as it would at inference time.

E3

Where invertibility dies, and a prediction that was wrong

The plan predicted near chance decoding through Linear(8192, 768), because that map has a 7,424 dimensional nullspace and no left inverse. That prediction is refuted, and the reason is worth more than the prediction was.

⌛

The caveat that stayed open, and how it closed

E3 used a random projection. A trained one might concentrate and lose the property that makes recovery work, so nothing was claimed end to end until that was checked. At first it looked like a refutation.

E4

Delete the output head: it works, and it costs something

Three heads, identical body, identical data, identical seeds. A unit trap governs this comparison: a vocabulary head's loss is nats per token, a byte head's is nats per byte position, at about 3.2 positions per token. Everything here is converted to nats per token.

E5

Is there any gradient at step 0?

The second objection: at random initialisation nothing is close to a real token, so there is nothing to decode. The plan predicted cross entropy would climb and an MSE regression head would not. Both climb.

What tying costs

E7

A vocabulary of 1M: a split verdict

The input vocabulary is deliberately small at 8,000 words. Thousands more appear only as targets, entering as an unknown marker. A vocabulary softmax scores exactly zero on those by construction, since no output row exists. The byte head scores zero too, and the control band below is what stops that being read as a refutation.

!

The mistake this assignment made three times

Three experiments were run on units that structurally could not exhibit the effect being measured, and each time the null looked like a finding.

wherethe flawhow it was caught
Problem 3, E5BPE tokens truncate 0.0024% of occurrences, so every codec carried identical informationan exposure diagnostic

Problem 5, E7rare in-vocabulary words score zero too, so a zero on unknown words proves nothinga rarity matched control band
Measure the exposure before believing a null. Two of these were only found by auditing the writeups against the literal wording of the brief.

What is not claimed. The byte head is not shown to be better: at this scale it is worse on loss, and its case rests on a parameter count at dimensions this machine cannot train. The 1M vocabulary payoff is neither demonstrated nor refuted. Everything trained here is 2 layers at d_model=96 on CPU with three seeds, quoted against a measured seed noise floor. The learned inverse is linear, so its recovery figures are a lower bound. Constrained decoding was not implemented, so the invalid UTF-8 rate is what an unconstrained argmax produces.
